5 Partition Detail — How Indices Split

The partition kernel reorders d_selected_examples in-place. For each node, rows where the projected value ≥ threshold go to the positive (left) side, others to negative (right).

6 Post-Training: OOB Evaluation

After the tree is fully built, the original host-side selected_examples (the sorted bootstrap indices before dedup) is used for out-of-bag evaluation at random_forest.cc:995.

UpdateOOBPredictionsWithNewTree() iterates all dataset rows, skipping those present in selected_examples (the in-bag set) to compute out-of-bag predictions. This is why even in NO_D2H mode, a D→H copy happens before dedup when OOB is enabled.

Key insight — NO_D2H eliminates the per-depth round-trip. In NO_D2H mode, selected_examples lives exclusively on device after bootstrap. The host tracks only offsets and counts while the GPU owns the actual index data. Without NO_D2H, every depth does a full H→D copy of flattened indices and a D→H copy of partitioned results.
